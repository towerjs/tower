## Vision

Beacon brings realtime to Tower applications: WebSocket pub/sub channels, presence, and an in-process event bus — behind one stable API. Like every Tower module, the transport is swappable; the channel API stays the same.

## Setup

```tsx filename="tower.config.ts"
beacon: {
  provider: 'postgres',   // LISTEN/NOTIFY on the Vault connection — no extra service
}
```

## Providers

| Provider   | Transport                        | Use case                   |

| `postgres` | Vault connection (LISTEN/NOTIFY) | Development and small apps |

## Channels

A **channel** is a named topic with a scope (e.g. `room:42`, `user:5`). Open channels through the `beacon` facade, mirroring how Vault and Gatehouse expose their APIs:

```tsx
import { beacon } from 'towerjs/beacon'

const chat = beacon.channel('room:42')

chat.publish('message', { user: 'alice', text: 'hello' })

const unsubscribe = chat.subscribe((event) => {
  console.log('received', event)
})
```

## Presence

```tsx
await chat.presence.join({ userId: 'usr_1' })
const members = await chat.presence.list()
```

## Internal events

Beyond WebSocket traffic, Beacon exposes an in-process event bus for module-to-module communication. Vault emits `vault:record:*` events, which you can bridge to channels:

```tsx
beacon.on('vault:record:created', async ({ table, id }) => {
  if (table === 'messages') {
    await beacon.channel(`room:${id}`).publish('message:created', { id })
  }
})
```

## WebSocket endpoint (Next.js)

```tsx filename="app/api/beacon/route.ts"
import { beacon } from 'towerjs/beacon/next'

export const GET = beacon.GET // WebSocket upgrade and message handling
export const POST = beacon.POST // client-to-server events
```

## Integration with Tower

- **Gatehouse** — authorize channel access from the session; presence is scoped to authenticated users
- **Vault** — bridge `vault:record:*` events to channels
- **Crane** — emit `job:completed` events to connected clients

## Planned features

- Automatic reconnection with backoff (client SDK)
