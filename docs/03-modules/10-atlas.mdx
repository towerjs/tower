## Vision

Atlas gives you file-based routing in any framework. Your route tree is derived from the file system, mapped to URL patterns, and served through a single handler. Next.js ships its own App Router, so Atlas targets frameworks that don't provide routing — Express, Hono, Fastify — or teams that want the same convention everywhere.

## Setup

```tsx filename="tower.config.ts"
atlas: {
  routesDir: './src/routes',
}
```

## Route files

```
src/routes/
  index.tsx          -> /
  about.tsx          -> /about
  blog/
    [slug].tsx       -> /blog/:slug
    [slug]/
      comments.tsx   -> /blog/:slug/comments
  api/
    users/
      [id].tsx       -> /api/users/:id
```

Each file exports a handler and optional metadata:

```tsx filename="src/routes/dashboard/settings.tsx"
export const route = {
  layout: 'dashboard',
  middleware: ['auth'],
  method: 'get',
}

export default function handler(req: AtlasRequest) {
  return atlas.json({ ok: true })
}
```

## Mounting

```tsx
import express from 'express'
import { atlas } from 'towerjs/atlas'

const app = express()
app.use(atlas.handler())
```

## Route metadata

- `layout` — wrap the route in a layout file
- `middleware` — named middleware chain
- `method` — restrict to a single HTTP method (default: all)

## Planned features

- Adapters for Hono, Express, Fastify, and Astro (middleware ordering, context)
- Automatic OpenAPI generation from route metadata
- Route loaders for data fetching
