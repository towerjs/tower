---
title: "Headless AI UI"
description: "Behavior-first React primitives for building AI interfaces."
---

Sorcerer provides headless React primitives for building AI interfaces.

The primitives provide behavior, state management, and accessibility while leaving styling completely to the application.

```tsx
import {
  Conversation,
  Message,
  PromptInput,
  PromptInputTextarea,
  PromptInputSubmit,
} from "towerjs/sorcerer/react"
```

A complete chat interface can be composed from primitives:

```tsx
function Chat() {
  return (
    <Conversation>
      <MessageList />

      <PromptInput>
        <PromptInputTextarea />

        <PromptInputSubmit />
      </PromptInput>
    </Conversation>
  )
}
```

Sorcerer does not provide a visual design system. Components can be styled with any approach:

* Tailwind CSS
* CSS modules
* styled-components
* custom design systems

Every primitive accepts an `asChild` prop. With `asChild`, the primitive does not render its own element — it clones the child and merges in the behavior, state, and accessibility props, so existing components from any component library can be used directly.

## Prompt Input

The prompt input handles common AI interaction patterns.

```tsx
<PromptInput onSubmit={send}>
  <PromptInputTextarea />

  <PromptInputAttachments />

  <PromptInputToolbar>
    <ModelSelector value={selectedModel} onChange={setSelectedModel}>
      <ModelSelectorButton>{selectedModel}</ModelSelectorButton>
    </ModelSelector>

    <PromptInputSubmit />
  </PromptInputToolbar>
</PromptInput>
```

Prompt input primitives support:

* message submission
* attachments
* file uploads
* model selection
* loading states
* streaming states
* keyboard interactions

## Messages

AI messages are structured content, not just text.

```tsx
<Message message={message}>
  <MessageContent>
    <MessageMarkdown />
  </MessageContent>
</Message>
```

Messages can contain:

* text
* markdown
* tool calls
* tool results
* reasoning
* sources
* attachments

Example:

```tsx
<AssistantMessage message={message}>
  <MessageMarkdown />

  <ToolCalls />

  <Sources />
</AssistantMessage>
```

## Streamdown Integration

Sorcerer uses Streamdown internally for progressive markdown rendering.

```tsx
<MessageMarkdown />
```

provides streaming-aware markdown rendering while remaining customizable.

Applications can replace individual renderers to match their own UI.

## Model Selection

Applications can expose model selection through headless primitives.

`ModelSelector` wraps Headless UI's `Listbox`, so the API follows the same compound-component pattern:

```tsx
import { ModelSelector } from "towerjs/sorcerer/react"

<ModelSelector value={selectedModel} onChange={setSelectedModel}>
  <ModelSelectorButton>{selectedModel}</ModelSelectorButton>

  <ModelSelectorOptions anchor="bottom">
    {availableModels.map((model) => (
      <ModelSelectorOption key={model} value={model}>
        {model}
      </ModelSelectorOption>
    ))}
  </ModelSelectorOptions>
</ModelSelector>
```

Tower does not decide what "smart" means — the application does. Each option renders the actual model string, or whatever the application chooses to display.

### asChild

Every ModelSelector element supports `asChild`, so it can compose with an existing component library instead of rendering its own element.

With `asChild`, Sorcerer does not render its own markup. It clones the child and merges in the props that drive selection behavior, accessibility, and state — the same contract as Headless UI and Radix.

```tsx
import { Button, Dropdown } from "@/components/ui"

<ModelSelector value={selectedModel} onChange={setSelectedModel}>
  <ModelSelectorButton asChild>
    <Button variant="outline">{selectedModel}</Button>
  </ModelSelectorButton>

  <ModelSelectorOptions asChild>
    <Dropdown.Content>
      {availableModels.map((model) => (
        <ModelSelectorOption key={model} value={model} asChild>
          <Dropdown.Item>{model}</Dropdown.Item>
        </ModelSelectorOption>
      ))}
    </Dropdown.Content>
  </ModelSelectorOptions>
</ModelSelector>
```

Sorcerer never nests a Headless UI element inside your component library — it hands the props down to the child instead.

For the server-side conversation APIs these primitives render, see [Chat](/docs/sorcerer/chat).
