Once a user signs in, a session cookie is set. Here's how to read it in every part of your app — and how to manage and revoke sessions.

## Reading the session

| Method                         | Context                  | Returns                                   |
| ------------------------------ | ------------------------ | ----------------------------------------- |
| `gatehouse.getSession()`       | Server (request context) | `{ user, session } \| null`               |
| `gatehouse.user()`             | Server (request context) | `GatehouseUser \| null`                   |
| `gatehouse.requireUser()`      | Server (request context) | `GatehouseUser` or throws                 |
| `gatehouseClient.useSession()` | Client component         | React hook, subscribes to session changes |

## Server components

```tsx filename="app/layout.tsx"
import { gatehouse } from 'towerjs/gatehouse'

export default async function RootLayout({ children }) {
  const session = await gatehouse.getSession()

  return (
    <header>{session ? `Hi, ${session.user.name}` : <a href="/sign-in">Sign in</a>}</header>
    // ...
  )
}
```

## Server actions

Server actions run inside an action context (`action()`), which wires up the request context automatically — `gatehouse.*` just works:

```tsx
'use server'

import { gatehouse } from 'towerjs/gatehouse'

export async function updateProfileName(name: string) {
  const user = await gatehouse.requireUser()
  await gatehouse.account.update({ name })

  return { ok: true }
}
```

## Route handlers

Route handlers are outside the action context — create a per-request instance, or wrap with `runWithRequest`:

```tsx filename="app/api/me/route.ts"
import { Gatehouse } from '@towerjs/gatehouse'

export async function GET(request: Request) {
  const gh = await Gatehouse.from(request)
  const user = await gh.user()

  return Response.json({ user })
}
```

```tsx
import { runWithRequest } from '@towerjs/gatehouse'

export async function GET(request: Request) {
  return runWithRequest(request, async () => {
    const user = await gatehouse.user()

    return Response.json({ user })
  })
}
```

## The client

```tsx
'use client'

import { gatehouseClient } from 'towerjs/gatehouse/client'

function ProfileButton() {
  const { data: session, isPending } = gatehouseClient.useSession()
  if (isPending) return null

  return session ? <span>{session.user.name}</span> : <a href="/sign-in">Sign in</a>
}
```

Use `useSession` for presentation only — authorize on the server.

## Session behavior

```tsx filename="tower.config.ts"
gatehouse: {
  session: {
    expiresIn: 604800,              // 7 days
    updateAge: 86400,               // sliding expiry after 1 day
    disableSessionRefresh: false,
  },
}
```

- Sessions are stored in the database and refreshed on activity (sliding expiry)
- `updateAge` — a session touched after this age gets its expiry extended
- `disableSessionRefresh` — turn sliding expiry off entirely

## Revocation

```tsx
await gatehouse.sessions.list() // all sessions for the user
await gatehouse.sessions.revoke(token)
await gatehouse.sessions.revokeOther() // everywhere except this device
await gatehouse.sessions.signOut() // current session
```

Actions: `revokeSession` (`token`), `revokeOtherSessions`. Revocation is immediate — the session is deleted from the database.

## Errors

`requireUser()` throws `AuthenticationError` when there's no session. The proxy normally keeps such requests out — catch the error when you want to render an alternative state instead of letting it propagate:

```tsx
import { AuthenticationError } from '@towerjs/gatehouse'

try {
  const user = await gatehouse.requireUser()
} catch (error) {
  if (error instanceof AuthenticationError) return null // render the signed-out state
  throw error
}
```

`ContextRequiredError` means a request-scoped method ran outside a request context (e.g. in a route handler without `Gatehouse.from`).
