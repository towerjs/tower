Gatehouse supports traditional email/password authentication with configurable email verification and password recovery.

## Enable

Credentials authentication is enabled with a single config block:

```ts filename="tower.config.ts"
gatehouse: {
  credentials: {
    enabled: true,
  },
}
```

This gives you:

- email/password sign up
- email/password sign in
- password recovery
- optional email verification

## Sign up

The `signUp` action takes `name`, `email`, `password`:

```tsx filename="src/app/sign-up/sign-up-form.tsx"
'use client'

import { signUp } from '@towerjs/tower/gatehouse/actions'

import { useActionState } from 'react'

export function SignUpForm() {
  const [state, action, pending] = useActionState(signUp, undefined)

  return (
    <form action={action}>
      {state?.error && <p role="alert">{state.error}</p>}
      <input name="name" required placeholder="Name" />
      <input name="email" type="email" required placeholder="Email" />
      <input name="password" type="password" required placeholder="Password" />
      <button type="submit" disabled={pending}>
        Sign up
      </button>
    </form>
  )
}
```

## Email verification

After signup, you can configure how users prove ownership of their email. Gatehouse supports three independent choices:

1. How users verify their email — by link or by one-time code
2. Whether unverified users can sign in
3. Whether verification creates a session automatically

### Verification link

The default web flow. Sign-up emails a link; clicking it verifies the email.

```text
Sign up
  ↓
Verification email sent
  ↓
User clicks link
  ↓
Email verified
  ↓
Session created (optional)
```

```ts filename="tower.config.ts"
gatehouse: {
  credentials: {
    enabled: true,
  },

  emailVerification: {
    sendOnSignUp: true,
    autoSignInAfterVerification: true,
  },
}
```

Good for:

- consumer apps and SaaS
- anything with a password-based account

The link email goes through [Courier](/docs/courier) when it's configured — no callback setup needed. Send the link on demand with `gatehouse.email.sendVerification({ email })`.

### Email OTP

Instead of a link, users enter a six-digit code from their email.

```text
Sign up
  ↓
Six-digit code sent
  ↓
User enters code
  ↓
Email verified
```

```ts filename="tower.config.ts"
gatehouse: {
  credentials: {
    enabled: true,
  },

  emailVerification: {
    method: 'otp',
  },
}
```

Send and confirm the code on the server:

```ts
await gatehouse.email.otp.send({ email, type: 'email-verification' })
await gatehouse.email.otp.confirm({ email, otp })
```

Good for:

- mobile apps and devices where opening email links is inconvenient
- passwordless-style flows — OTP also works as a sign-in method, see [Magic Links & OTP](/docs/gatehouse/magic-links)

### Require verification before sign in

#### Allow unverified sign in

```ts filename="tower.config.ts"
gatehouse: {
  emailVerification: {
    required: false,
  },
}
```

```text
Sign up
  ↓
Account created
  ↓
User can sign in
  ↓
Verify email later
```

Useful when verification is a reminder rather than a hard requirement.

#### Require verification first

```ts filename="tower.config.ts"
gatehouse: {
  emailVerification: {
    required: true,
  },
}
```

```text
Sign up
  ↓
Verified?
  ↓
Sign in blocked until email is verified
```

Recommended for SaaS products, public sign-ups, and preventing fake accounts.

### Session after verification

#### Automatically create a session

```ts filename="tower.config.ts"
emailVerification: {
  autoSignInAfterVerification: true,
}
```

```text
Click verification link
        ↓
Email verified
        ↓
Signed in — straight into the app
```

The smoothest onboarding: the user never returns to the sign-in form.

#### Require sign in

```ts filename="tower.config.ts"
emailVerification: {
  autoSignInAfterVerification: false,
}
```

```text
Click verification link
        ↓
Email verified
        ↓
Sign in page
        ↓
Dashboard
```

Useful when:

- you want explicit authentication
- verification happens on a separate device
- your security model requires a fresh login

## Recommended configurations

### Standard SaaS

```ts filename="tower.config.ts"
gatehouse: {
  credentials: {
    enabled: true,
  },

  emailVerification: {
    required: true,
    sendOnSignUp: true,
    autoSignInAfterVerification: true,
  },
}
```

Sign up → verify by link → signed in. Unverified users can't sign in.

### Internal app

```ts filename="tower.config.ts"
gatehouse: {
  credentials: {
    enabled: true,
  },
}
```

Accounts work immediately; verification is optional or added later.

### Mobile-style verification

```ts filename="tower.config.ts"
gatehouse: {
  credentials: {
    enabled: true,
  },

  emailVerification: {
    method: 'otp',
  },
}
```

Users prove their email by entering a code — good on devices where links are awkward.

Fine-tuning knobs (password length, reset-token expiry, sign-up session behavior, custom email handlers) are documented in the [configuration reference](/docs/gatehouse/api-reference/configuration).

## Forgot & reset password

Two actions, two forms. First request the reset email:

```tsx filename="src/app/forgot-password/forgot-password-form.tsx"
'use client'

import { requestPasswordReset } from '@towerjs/tower/gatehouse/actions'

import { useActionState } from 'react'

export function ForgotPasswordForm() {
  const [state, action, pending] = useActionState(requestPasswordReset, undefined)

  return (
    <form action={action}>
      {state?.ok ? (
        <p>Check your email for a reset link.</p>
      ) : (
        <>
          {state?.error && <p role="alert">{state.error}</p>}
          <input name="email" type="email" required placeholder="Email" />
          <button type="submit" disabled={pending}>
            Send reset link
          </button>
        </>
      )}
    </form>
  )
}
```

Then the reset form, reading the token from the link query param:

```tsx filename="src/app/reset-password/reset-password-form.tsx"
'use client'

import { resetPassword } from '@towerjs/tower/gatehouse/actions'

import { useActionState, useSearchParams } from 'next/navigation'

export function ResetPasswordForm() {
  const [state, action, pending] = useActionState(resetPassword, undefined)
  const token = useSearchParams().get('token') ?? ''

  return (
    <form action={action}>
      {state?.error && <p role="alert">{state.error}</p>}
      <input type="hidden" name="token" value={token} />
      <input name="newPassword" type="password" required placeholder="New password" />
      <button type="submit" disabled={pending}>
        Reset password
      </button>
    </form>
  )
}
```

The reset email itself goes through [Courier](/docs/courier) when the module is configured — no callback setup needed. Reset tokens are single-use and expire.

## Change password & email

```ts
await gatehouse.password.change({ currentPassword, newPassword }) // signed-in users
await gatehouse.account.changeEmail(newEmail)
```

The `changePassword` action takes `currentPassword` + `newPassword`; `changeEmail` takes `newEmail`.
