---
title: 'API Keys'
description: 'Scoped keys for programmatic access — create, verify, rotate, and revoke.'
---

API keys let services (CLIs, webhooks, cron jobs) authenticate without a user session. Each key carries a permission map that limits what it can do.

## Enable

```ts signature
import { gatehouse } from '@towerjs/gatehouse'

gatehouse({
  provider: 'better-auth',
  appName: 'My App',
  apiKey: true,
})
```

## Create a key

```ts signature
import { gatehouse } from '@towerjs/gatehouse'

await gatehouse.apiKeys.create({
  name: 'Deploy CLI',
  userId: 'user_123', // required — the key's owner
  expiresIn: 30 * 86400, // optional, seconds
  permissions: { project: ['deploy'] },
})
```

The key is returned **once** — store it where the service can read it. `prefix` (a string your app brands the key with), `metadata`, and `organizationId` are also supported.

Action: `createApiKey` (`name`, `expiresIn`) — returns `{ ok: true }` or `{ error }`; the key itself isn't returned by the action, so create keys from a server context where `apiKeys.create()` is available.

## Verify

Verify on every programmatic request — the provider returns a verification result:

```ts signature
import { gatehouse } from '@towerjs/gatehouse'

const { valid, error, key } = await gatehouse.apiKeys.verify({ key: 'tower_live_...' })
if (!valid) return Response.json({ error: error?.message ?? 'Invalid key' }, { status: 401 })
// key is Omit<ApiKeyInfo, 'key'> | null — available only when valid
```

`permissions` and `configId` can be passed to enforce scoped verification:

```ts signature
const result = await gatehouse.apiKeys.verify({
  key: 'tower_live_...',
  permissions: { project: ['deploy'] },
})
if (!result.valid) return Response.json({ error: 'Forbidden' }, { status: 403 })
```

Route-handler guard:

```ts signature filename="src/app/api/deploy/route.ts"
import { gatehouse from '@towerjs/gatehouse'

export async function POST(request: Request) {
  const token = request.headers.get('Authorization')?.replace('Bearer ', '') ?? ''
  const { valid, error, key } = await gatehouse.apiKeys.verify({ key: token })
  if (!valid || !key) return Response.json({ error: error?.message ?? 'Invalid key' }, { status: 401 })
  if (!key.permissions?.['project']?.includes('deploy')) {
    return Response.json({ error: 'Forbidden' }, { status: 403 })
  }
  // ...
}
```

## List, rotate, revoke

```ts signature
import { gatehouse } from '@towerjs/gatehouse'

const userId = 'usr_123'
const keyId = 'key_123'

await gatehouse.apiKeys.list(userId, { sortBy: 'createdAt' })
await gatehouse.apiKeys.get(keyId)
await gatehouse.apiKeys.update(keyId, { name: 'CI deploy', expiresIn: 30 * 86400 }) // rotate expiry or permissions
await gatehouse.apiKeys.delete(keyId)
```

Actions: `updateApiKey` (`id`, `name`), `deleteApiKey` (`id`), `verifyApiKey` (`key`, `permissions?`, `configId?`) — returns `{ valid, error, key }`.

## Key properties

| Field            | Description                                                            |
| ---------------- | ---------------------------------------------------------------------- |
| `name`           | Human-readable label                                                   |
| `prefix`         | Branded prefix (e.g. `tower_live_`) — keys start with it               |
| `permissions`    | Permission map: `{ 'resource': ['action'] }` — checked against `can()` |
| `metadata`       | Free-form object                                                       |
| `expiresAt`      | Expiry; expired keys fail verification                                 |
| `organizationId` | Optional organization scope                                            |

## Notes

- Keys are hashed at rest — only the plaintext is shown at creation
- Combine with [Authorization](/docs/gatehouse/authorization): `can()` and key permission maps use the same shape
- `verifyApiKey` action returns `{ ok: true }` or `{ error }` — the key data isn't returned
