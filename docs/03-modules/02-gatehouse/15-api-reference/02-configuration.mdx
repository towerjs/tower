Gatehouse is configured under the `gatehouse` key in `tower.config.ts`. Features are opt-in — omit a feature to disable it.

```tsx filename="tower.config.ts"
gatehouse: {
  provider: 'better-auth',
  appName: 'My App',
  baseURL: 'http://localhost:3000',

  // Enable auth methods
  credentials: { enabled: true },
  emailVerification: { method: 'link', sendOnSignUp: true, autoSignInAfterVerification: true },
  social: { google: {}, github: {} },
  magicLinks: true,
  phoneNumber: true,
  passkeys: true,
  twoFactor: true,
  organization: true,
  admin: true,
  apiKey: true,
}
```

## Core

| Option | Type | Description |
| --- | --- | --- |
| `provider` | `'better-auth'` | The auth provider backend |
| `appName` | `string` | App name used in auth emails and TOTP labels |
| `baseURL` | `string \| object` | Canonical app URL; object form accepts `allowedHosts`, `protocol`, `fallback` |
| `trustedOrigins` | `string[]` | Additional trusted origins for cross-origin auth |
| `plugins` | `BetterAuthPlugin[]` | Extra Better Auth plugins |

**Secret** — there's no `secret` option. The cookie-signing secret comes from `passThrough.secret`, `GATEHOUSE_SECRET`, or `BETTER_AUTH_SECRET` (outside production, a dev fallback applies).

## credentials

Email/password auth. `true` enables it with defaults; an object configures behavior:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `enabled` | `boolean` | — | Enable credentials auth |
| `disableSignUp` | `boolean` | `false` | Email/password sign-up off (invite-only apps) |
| `requireEmailVerification` | `boolean` | `false` | Deprecated — moved to `emailVerification.required` |
| `minPasswordLength` | `number` | `8` | Minimum password length |
| `maxPasswordLength` | `number` | — | Maximum password length |
| `autoSignIn` | `boolean` | `true` | Create a session immediately after sign-up |
| `revokeSessionsOnPasswordReset` | `boolean` | `true` | Sign out all devices after a reset |
| `resetPasswordTokenExpiresIn` | `number` | — | Reset token lifetime in seconds |
| `sendResetPassword` | `fn` | courier | Custom password-reset email handler |
| `onPasswordReset` | `fn` | — | Called after a password reset |
| `onExistingUserSignUp` | `fn` | — | Called when sign-up matches an existing user |
| `customSyntheticUser` | `fn` | — | Customize the synthetic user created for OAuth/OTP flows |
| `password.hash` / `password.verify` | `fn` | scrypt | Custom password hashing |

## emailVerification

How users prove they own their email. `true` enables it with default behavior (link method, not required); an object configures it:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `enabled` | `boolean` | — | Enable email verification |
| `method` | `'link' \| 'otp'` | `'link'` | Verify by clicking a link, or by entering a one-time code. `'otp'` also enables one-time-code sign-in (`gatehouse.signIn.emailOtp`) |
| `required` | `boolean` | `false` | Block sign-in until the email is verified (unless signed in via OTP, which proves ownership) |
| `sendOnSignUp` | `boolean` | `false` | Send the verification link/code at sign-up |
| `autoSignInAfterVerification` | `boolean` | `true` | Create a session when the email is verified |
| `expiresIn` | `number` | — | Verification token/code lifetime in seconds |
| `sendVerificationEmail` | `fn` | courier | Custom verification link handler (`method: 'link'`) |
| `sendVerificationOTP` | `fn` | courier | Custom verification code handler (`method: 'otp'`) |

`sendVerificationOTP` receives `{ email, otp, type }` where `type` is `'sign-in'`, `'email-verification'`, `'forget-password'`, or `'change-email'`.

## social

Provider list or map. Credentials resolve from env vars (`GOOGLE_CLIENT_ID`, etc.):

```tsx
social: ['google', 'github'],
// or
social: {
  google: {
    disableSignUp: true,
    scope: ['openid', 'profile', 'email'],
  },
},
```

Per-provider options: `clientId`, `clientSecret`, `scope`, `redirectURI`, `disableSignUp`, `disableImplicitSignUp`, `overrideUserInfoOnSignIn`, `prompt`, `responseMode`.

## magicLinks

`true` enables it. Only `sendMagicLink` (defaults to Courier) is honored — options like `callbackURL` and link expiry are currently not passed to the plugin.

## phoneNumber

`true` enables it. Only `sendOTP` (defaults to Courier SMS) is honored — OTP expiry and other options are currently not passed to the plugin.

## passkeys

`true` enables WebAuthn. Object form passes options to the Better Auth passkey plugin (relying party config, etc.).

## twoFactor

`true` enables TOTP. The plugin is currently instantiated with no options — the object form is typed but reserved (no 2FA options are passed yet).

## organization

`true` enables organizations. The plugin is currently instantiated with no options — the object form is typed but reserved.

## admin

`true` enables the admin API. The plugin is currently instantiated with no options — the object form is typed but reserved.

## apiKey

`true` enables API keys. Options map to the `@better-auth/api-key` plugin (default expiry, hashing).

## passThrough

Raw Better Auth options spread onto the `betterAuth()` config — anything not covered by the options above. Notably `passThrough.secret` supplies the signing secret (falling back to `GATEHOUSE_SECRET` / `BETTER_AUTH_SECRET`), and `passThrough.basePath` overrides the auth base path.

## Courier auto-wiring

When both `gatehouse` and `courier` are configured, auth emails go through Courier automatically — no callback configuration needed:

- Password reset emails (`credentials.sendResetPassword`)
- Email verification link (`emailVerification.sendVerificationEmail`)
- Email verification code (`emailVerification.sendVerificationOTP`, when `method: 'otp'`)
- Magic links (`magicLinks.sendMagicLink`)
- Phone OTP (`phoneNumber.sendOTP`)
