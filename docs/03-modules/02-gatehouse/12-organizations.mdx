Organizations let users belong to multiple workspaces, each with its own members, roles, and permissions.

## Enable

```ts
import { gatehouse } from '@towerjs/gatehouse'

gatehouse({
  provider: 'better-auth',
  appName: 'My App',
  organization: true,
})
```

## The lifecycle

**Create** — the creator becomes the owner:

```ts
import { gatehouse } from '@towerjs/gatehouse'

await gatehouse.organizations.create({ name: 'Acme', slug: 'acme' })
```

Action: `createOrganization` (`name`, `slug`).

**Invite** — email invites with a role:

```ts
import { gatehouse } from '@towerjs/gatehouse'

await gatehouse.organizations.invitations.create('org_id', {
  email: 'ada@example.com',
  role: 'member',
})
```

Action: `inviteMember` (`orgId`, `email`, `role`).

**Accept** — the invitee accepts (or rejects) and joins:

```ts
import { gatehouse } from '@towerjs/gatehouse'

const invitationId = 'inv_123'

await gatehouse.organizations.invitations.accept(invitationId)
await gatehouse.organizations.invitations.reject(invitationId)
await gatehouse.organizations.invitations.cancel(invitationId)
```

Actions: `acceptInvitation` / `rejectInvitation` (`invitationId`), `cancelInvitation`.

**Switch** — users work in one organization at a time:

```ts
import { gatehouse } from '@towerjs/gatehouse'

const organizationId = 'org_123'

await gatehouse.organizations.setActive(organizationId)
```

Action: `setActiveOrganization` (`organizationId`).

**Check** — `requireUser()` is per-user; query the active org for context:

```ts
import { gatehouse } from '@towerjs/gatehouse'

const orgs = await gatehouse.getOrganizations() // memberships
const org = await gatehouse.getOrganization('org_123') // full: members + invitations
```

## Members

```ts
import { gatehouse } from '@towerjs/gatehouse'

const userId = 'usr_123'
const organizationId = 'org_123'
const memberId = 'mem_123'

await gatehouse.organizations.members.add(organizationId, userId, 'member')
await gatehouse.organizations.members.update(memberId, 'admin', organizationId)
await gatehouse.organizations.members.remove(organizationId, memberId)
```

Actions: `addMember` (`organizationId`, `email`, `role`), `updateMemberRole` (`memberId`, `role`, `organizationId`), `removeMember` (`orgId`, `memberId`).

## Custom roles

```ts
import { gatehouse } from '@towerjs/gatehouse'

await gatehouse.organizations.roles.create({
  role: 'editor',
  permission: { project: ['update'] },
})
```

```ts signature
await gatehouse.organizations.roles.list(organizationId?)
await gatehouse.organizations.roles.get({ roleName: 'editor', organizationId })
await gatehouse.organizations.roles.update(roleId, { roleName?, permission? })
await gatehouse.organizations.roles.delete({ roleId | roleName, organizationId })
```

Roles are managed from the server API — see [Authorization](/docs/gatehouse/authorization) for permission semantics.

Built-in roles: `owner`, `admin`, `member` — see [Authorization](/docs/gatehouse/authorization) for permission semantics.

## Permission checks

```ts
import { Gatehouse } from '@towerjs/gatehouse'

export async function GET(request: Request) {
  const gh = await Gatehouse.from(request)
  const user = await gh.requireUser()

  const allowed = await gh.can({
    user,
    permission: 'project.update',
    organizationId: 'org_123', // scope the check to an org
  })

  return Response.json({ allowed })
}
```

Permission checks live on the per-request instance. Resource-level rules belong in a policy — see [Authorization](/docs/gatehouse/authorization).

## Invitation fields

`OrganizationInvitation` carries `email`, `role`, `status` (`pending` / `accepted` / `rejected` / `canceled`), `inviterId`, `expiresAt`. List and inspect before rendering invite UI:

```ts
import { gatehouse } from '@towerjs/gatehouse'

const organizationId = 'org_123'
const invitationId = 'inv_123'

await gatehouse.organizations.invitations.list(organizationId)
await gatehouse.organizations.invitations.get(invitationId)
```

## Notes

- Organization membership is separate from authentication — a signed-in user may belong to zero or many organizations
- The active organization is per-user; remember it and pass `organizationId` explicitly for scoped operations
- Deleting an organization removes memberships, invitations, and roles
