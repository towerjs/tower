---
title: "Passkeys"
description: "Passwordless WebAuthn sign-in with device-bound keys."
---

Passkeys replace passwords with WebAuthn credentials stored on the user's device — Touch ID, Face ID, Windows Hello, or a security key. There's nothing to remember and nothing to phish.

## Enable

```tsx filename="tower.config.ts"
gatehouse: {
  provider: 'better-auth',
  appName: 'My App',
  passkeys: true,
}
```

## Register a passkey

Passkey registration is a WebAuthn ceremony driven from a signed-in context. `gatehouseClient` has no passkey plugin, so use the server API's raw passkey endpoints through `gatehouse.api`:

```tsx filename="app/settings/passkeys/actions.ts"
'use server'

import { gatehouse } from 'towerjs/gatehouse'

export async function generateRegistrationOptions() {
  return gatehouse.api.generatePasskeyRegistrationOptions()
}
```

```tsx filename="app/settings/passkeys/register-passkey.tsx"
'use client'

export function RegisterPasskey() {
  async function handleRegister() {
    const opts = await generateRegistrationOptions()
    const credential = await navigator.credentials.create({ publicKey: opts })
    await verifyRegistration('/api/auth/passkey/verify-registration', credential)
  }
  return <button onClick={handleRegister}>Add passkey</button>
}
```

The raw endpoints — `generatePasskeyRegistrationOptions`, `verifyPasskeyRegistration`, `generatePasskeyAuthenticationOptions`, `verifyPasskeyAuthentication` — handle the WebAuthn flow and are available on `gatehouse.api`.

## Sign in with a passkey

Passkey sign-in runs the WebAuthn ceremony in the browser via `gatehouse.api.generatePasskeyAuthenticationOptions` / `gatehouse.api.verifyPasskeyAuthentication`; the browser prompts for the device credential and the session is created on success.

## Manage passkeys

List, rename, and remove from the server:

```tsx
await gatehouse.passkeys.list()       // [{ id, name, createdAt }]
await gatehouse.passkeys.update(id, { name })
await gatehouse.passkeys.delete(id)
```

Actions: `updatePasskey` (`id`, `name`), `deletePasskey` (`id`).

## Notes

- Users must already have a session to register a passkey — pair with email/password or magic links for first sign-in
- Passkeys are device-bound, not syncable — users should register more than one
