title: 'Scribe'
description: 'The Tower CLI. Scaffolds new applications (tower create) and manages databases (tower migrate, tower seed).'
---

Scribe is the CLI behind `pnpm create tower`, `tower migrate`, and `tower seed`.

## Usage

```bash
pnpm create tower
```

This prompts for:

- Project name
- Which modules to include (Vault, Gatehouse, Courier)
- Optional: social auth providers, email provider, etc.

For non-interactive use (scripts, CI), pass flags instead:

```bash
pnpm create tower my-app \
  --no-tailwind \
  --modules vault,gatehouse \
  --vault neon \
  --features credentials,phoneNumber \
  --email resend \
  --sms twilio
```

Available flags:

| Flag                                                 | Values                                                                                             | Default         |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------- |
| `--name` / `--project-name`, or positional first arg | project name                                                                                       | `my-app`        |
| `--tailwind` / `--no-tailwind`                       | —                                                                                                  | `--no-tailwind` |
| `--deployment`                                       | `vercel`, `cloudflare`, `other`                                                                    | `vercel`        |
| `--modules`                                          | comma-separated: `vault`, `gatehouse`, `courier`                                                   | none            |
| `--vault`                                            | `neon`, `supabase`, `railway`, `other`, `skip`                                                     | `skip`          |
| `--features`                                         | comma-separated: `credentials`, `social`, `magicLinks`, `twoFactor`, `organization`, `phoneNumber` | none            |
| `--email`                                            | `resend`, `smtp`, `ses`, `skip`                                                                    | `skip`          |
| `--sms`                                              | `twilio`, `skip`                                                                                   | `skip`          |

Passing any flag runs the whole flow without prompting.

Once installed, projects also get the `tower` binary for database work:

```bash
npx tower migrate          # Run database migrations
npx tower migrate --seed   # Migrate then seed (-s for shorthand)
npx tower seed             # Run seeds (migrations first by default)
npx tower seed --skip-migrate  # Seeds only
npx tower --version        # Show version
npx tower help             # List commands
```

The scaffolded project includes:

- Next.js with App Router
- Tower configuration (`tower.config.ts`)
- Auth wiring (proxy, API routes) when gatehouse is selected
- Database configuration
- TypeScript and build tooling
- A minimal placeholder homepage — Tower does not generate application UI

## Output

```text
my-app/
├── src/
│   ├── proxy.ts                     # gatehouse only
│   └── app/
│       ├── api/auth/[...all]/route.ts   # gatehouse only
│       ├── layout.tsx
│       └── page.tsx
│   └── vault/
│       ├── migrations/              # vault only (kept with .gitkeep)
│       └── seeds/                   # vault only (kept with .gitkeep)
├── tower.config.ts
├── next.config.ts                   # edge runtime only
├── package.json
├── tsconfig.json
├── .env.example
├── .prettierrc
└── AGENTS.md
```

Vault projects get `src/vault/migrations/` and `src/vault/seeds/` out of the box — scaffolded with `.gitkeep` files so the folders exist before your first migration or seed. Drop your migration and seed files in there (see [Vault](/docs/vault)).
