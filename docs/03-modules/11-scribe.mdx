Scribe is the CLI behind `pnpm create tower`, `tower migrate`, and `tower seed`.

## Usage

```bash
pnpm create tower
```

This prompts for:

- Project name
- TypeScript or JavaScript
- Tailwind CSS
- Which modules to include (Vault, Gatehouse, Courier)
- Optional: social auth providers, email provider, etc.

For non-interactive use (scripts, CI), pass flags instead:

```bash
pnpm create tower my-app \
  --no-tailwind \
  --modules vault,gatehouse \
  --vault neon \
  --features credentials,phoneNumber \
  --email resend \
  --sms twilio
```

Available flags:

| Flag                                                 | Values                                                                                             | Default         |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------- |
| `--name` / `--project-name`, or positional first arg | project name                                                                                       | `my-app`        |
| `--ts` / `--js`                                      | —                                                                                                  | `--ts`          |
| `--tailwind` / `--no-tailwind`                       | —                                                                                                  | `--no-tailwind` |
| `--deployment`                                       | `vercel`, `cloudflare`, `other`                                                                    | `vercel`        |
| `--modules`                                          | comma-separated: `vault`, `gatehouse`, `courier`                                                   | none            |
| `--vault`                                            | `neon`, `supabase`, `railway`, `other`, `skip`                                                     | `skip`          |
| `--features`                                         | comma-separated: `credentials`, `social`, `magicLinks`, `twoFactor`, `organization`, `phoneNumber` | none            |
| `--email`                                            | `resend`, `smtp`, `ses`, `skip`                                                                    | `skip`          |
| `--sms`                                              | `twilio`, `skip`                                                                                   | `skip`          |

Passing any flag runs the whole flow without prompting.

Once installed, projects also get the `tower` binary for database work:

```bash
npx tower about                # Show app, module, runtime, and environment diagnostics
npx tower migrate              # Run database migrations
npx tower migrate --seed       # Migrate then seed (-s for shorthand)
npx tower seed                 # Run seeds (migrations first by default)
npx tower seed --skip-migrate  # Seeds only
npx tower --version            # Show version
npx tower help                 # List commands
```

Alternatively, with pnpm: `pnpm exec tower about` inside a project, or `pnpm dlx @towerjs/scribe about` without one. Note that `npx tower` works in a project because npx prefers the local `node_modules/.bin` — but `pnpm dlx tower` always fetches the npm package literally named `tower`, which is a different, unrelated package, so always name `@towerjs/scribe` with `dlx`.

The scaffolded project includes:

- Next.js with App Router
- Tower configuration (`tower.config.ts`, or `tower.config.js` for JavaScript projects)
- Auth wiring (proxy, API routes) when gatehouse is selected
- Database configuration
- TypeScript (default) or JavaScript, plus build tooling
- A minimal placeholder homepage — Tower does not generate application UI

JavaScript projects work the same as TypeScript ones: all Tower code — `tower.config.js`, `page.jsx`, `proxy.js`, and the auth `route.js` — is generated without type annotations, and the `tower` CLI loads `tower.config.js` natively.

## Output

```text
my-app/
├── src/
│   ├── proxy.ts                     # gatehouse only (proxy.js in JS projects)
│   └── app/
│       ├── api/auth/[...all]/route.ts   # gatehouse only (route.js in JS projects)
│       ├── layout.tsx
│       └── page.tsx                 # page.jsx in JS projects
│   └── vault/
│       ├── migrations/              # vault only (kept with .gitkeep)
│       └── seeds/                   # vault only (kept with .gitkeep)
├── tower.config.ts                  # tower.config.js in JS projects
├── next.config.ts                   # edge runtime only (next.config.mjs in JS projects)
├── package.json
├── tsconfig.json                    # omitted in JS projects
├── .env.example
├── .prettierrc
└── AGENTS.md
```

Vault projects get `src/vault/migrations/` and `src/vault/seeds/` out of the box — scaffolded with `.gitkeep` files so the folders exist before your first migration or seed. Drop your migration and seed files in there (see [Vault](/docs/vault)).

## The `tower` CLI

Every scaffolded app ships `tower` — run migrations, seeds, generators, diagnostics, and the dev server without leaving the project.

### `tower about` / `tower config`

```bash
npx tower about          # runtime, modules, providers, env diagnostics
npx tower config show    # resolved config — secrets redacted
npx tower config show --json
```

`config show` prints the resolved `tower.config.ts` with `*_SECRET`, `*_KEY`, `DATABASE_URL`, etc. redacted.

### `tower db` — database

`db` is the v0.2 command group for everything that touches the database. Legacy `tower migrate` / `tower seed` still work — `db` is the new, complete surface:

```bash
npx tower db migrate     # run pending vault + gatehouse migrations (stepped: one transaction per migration, re-runnable)
npx tower db rollback    # roll back the most recent migration
npx tower db status      # executed vs pending — checks kysely_migration table
npx tower db refresh     # rollback all, then re-migrate
npx tower db fresh       # DROP SCHEMA public CASCADE; CREATE SCHEMA public; migrate + seed (--force in production)
npx tower db seed        # run seeds (migrations first by default)
npx tower db seed --skip-migrate  # seeds only
npx tower db setup       # migrate + gatehouse migrate + seed — first-run helper
```

Flags for every destructive subcommand (`rollback`, `refresh`, `fresh`):

- `--pretend` — compile migrations against a `DummyDriver` and print the SQL instead of executing. Nothing is written.
- `--force` — required when `NODE_ENV=production` — without it, `fresh`/`refresh`/`rollback` in production either ask for interactive `yes` confirmation or (non-TTY) fail with an actionable error.
- Isolated execution — pending migrations run `migrateTo(target)` one-by-one so a failure leaves earlier migrations applied.

```bash
npx tower db migrate --pretend
npx tower db fresh --force   # production
```

The legacy form `npx tower migrate --seed` (`-s`) is still supported.

### `tower make` — generators

```bash
npx tower make model Project        # src/models/project.ts — typed class extending Model
npx tower make migration AddProjects # src/vault/migrations/0001_add-projects.ts — Kysely up/down stub
npx tower make policy Project       # src/policies/project.ts — definePolicy + registration
npx tower make factory Project       # src/factories/project.ts — defineFactory(Product, ({seq})=>...)
npx tower make job SendEmail         # src/jobs/send-email.ts — deferred work entry point
npx tower make --help                # list generators
```

Names are normalized: `Project` → `project` file + `projects` table. Migrations are numbered from existing migration count (`0001_...`, `0002_...`).

### `tower dev`

```bash
npx tower dev             # validate config + run diagnostics, then start `next dev`
```

- Runs Tower validation/diagnostics before the framework dev server.
- Always serves on `3000`; if `3000` is taken it falls back to the next free port and prints the chosen port.
- Wires `tower dev` as the `dev` script in generated `package.json` so `pnpm dev` is the canonical command.
