## Vision

Crane turns background work into plain function calls. Define a job, dispatch it — Crane handles persistence, retries, concurrency, and scheduling. The default provider runs on your existing Vault database, so there is no queue service to stand up.

## Setup

```tsx filename="tower.config.ts"
crane: {
  provider: 'postgres',   // job tables in the Vault database
  concurrency: 5,
  retries: 3,
  backoff: 'exponential',
}
```

Run `tower migrate` — Crane's migrations create the job tables.

## Providers

| Provider   | Description                                    |
| ---------- | ---------------------------------------------- |
| `postgres` | Built-in: jobs persisted in the Vault database |
| `redis`    | Redis-backed queues for multi-instance setups  |

## Jobs

```tsx
import { crane } from 'towerjs/crane'

crane.job('send-email', async (payload: { to: string; subject: string }) => {
  await courier.email.send({ ...payload, html: '<p>Welcome!</p>' })
})

await crane.dispatch('send-email', {
  to: 'user@example.com',
  subject: 'Welcome!',
})

// Delayed dispatch
await crane.dispatch('send-email', payload, { runAt: '2026-09-01T09:00:00Z' })
```

## Cron

```tsx
crane.cron('daily-report', '0 6 * * *', async () => {
  await generateReport()
})
```

## Worker

Crane polls for due jobs in-process — no separate worker process:

```tsx
await crane.start()  // start processing
await crane.stop()   // finish in-flight jobs, then exit
```

## Failures

Jobs that exhaust retries are marked failed and inspected through the facade:

```tsx
const failed = await crane.failed('send-email')
await crane.retry(failed[0].id)
```

## Integration with Tower

- **Vault** — job persistence and migration in the shared database
- **Beacon** — emit `job:completed` events to connected clients
- **Observatory** — log job lifecycle, retries, and latency
