### Project Structure

A freshly scaffolded Tower project includes:

```text
my-app/
├── src/
│   ├── proxy.ts                        # Auth middleware (gatehouse)
│   └── app/
│       ├── api/auth/[...all]/route.ts  # Auth API routes (gatehouse)
│       ├── layout.tsx
│       └── page.tsx                    # Minimal placeholder page
├── tower.config.ts
├── next.config.ts                      # Edge runtime only
├── package.json
└── tsconfig.json
```

The scaffold prompts for TypeScript (default) or JavaScript. JavaScript projects get the same structure with plain JS files — `tower.config.js`, `page.jsx`, `proxy.js`, and a `route.js` — and skip `tsconfig.json`. Tower provides types but doesn't require them.

Tower scaffolds the infrastructure — configuration, database, and auth wiring. It does not generate application UI: sign-in/sign-up pages, dashboards, and the rest are yours to build. The homepage is a minimal placeholder that says the application is ready.

## Build Your App

Tower is modular — pick the pieces your app needs. Each module page has complete, copy-paste setup including ready-made forms, so you can go from scaffold to working feature without styling:

- **[Add a database](/docs/vault)** — connection, migrations, seeds, and queries
- **[Add authentication](/docs/gatehouse/setup)** — sign-in, sign-up, sessions, organizations, and password reset, with copy-paste forms
- **[Send email](/docs/courier)** — email, SMS, and push providers

Want to see it assembled? The [Authentication with Gatehouse tutorial](/docs/tutorials/authentication) walks through a full sign-in → dashboard app.

## Manual Setup

Add Tower to an existing Next.js project:

### Install

<CodeTabs>
  <CodeTab title="pnpm">```bash pnpm add @towerjs/tower pnpm add -D @towerjs/scribe ```</CodeTab>
  <CodeTab title="npm">```bash npm install @towerjs/tower npm install -D @towerjs/scribe ```</CodeTab>
  <CodeTab title="yarn">```bash yarn add @towerjs/tower yarn add -D @towerjs/scribe ```</CodeTab>
  <CodeTab title="bun">```bash bun add @towerjs/tower bun add -D @towerjs/scribe ```</CodeTab>
</CodeTabs>

`@towerjs/scribe` provides the `tower` CLI (`tower migrate`, `tower seed`) — install it as a dev dependency.

`@towerjs/tower` bundles every module, so subpaths like `@towerjs/tower/vault`, `@towerjs/tower/courier`, and `@towerjs/tower/gatehouse` all work from a single install. Install an individual `@towerjs/*` package only when you import from it directly — for example, the auth proxy imports `gatehouse` from `@towerjs/gatehouse`, so add that package when you set up authentication ([Gatehouse setup](/docs/gatehouse/setup)).

> **Edge runtime only** — `@towerjs/edge` is only needed if you deploy to an edge runtime (Vercel Edge, Cloudflare Workers). Most apps run on the Node.js runtime and can skip it. If you do use an edge runtime, install it and wrap `next.config.ts`:
>
> ```bash
> pnpm add -D @towerjs/edge
> ```
>
> ```tsx filename="next.config.ts"
> import { withTowerEdge } from '@towerjs/edge'
>
> export default withTowerEdge({})
> ```

### 1. Configure tower.config.ts

Start with a minimal config and add the modules you need — each module page has the full configuration and copy-paste examples:

```ts filename="tower.config.ts"
import { defineTower } from '@towerjs/tower/blueprint'

export default defineTower({
  modules: {
    // Add modules as you need them.
    // vault: {},             // database — /docs/vault
    // gatehouse: {...},      // authentication — /docs/gatehouse/setup
    // courier: {...},        // email, SMS, push — /docs/courier
  },
})
```

### 2. Run migrations

If your app uses Vault — including Gatehouse's auth tables — set `DATABASE_URL` (or pass `connectionString` to `vault`), then:

```bash
npx tower migrate
```
