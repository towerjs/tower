---
title: 'towerjs'
description: 'The meta-package that bundles all Tower modules under a single dependency with lazy initialization.'
---

`towerjs` is the user-facing entry point. It re-exports from all `@towerjs/*` packages and adds lazy initialization — the app is initialized on first use, not at import time.

## Installation

```bash
pnpm add towerjs
```

## Subpath Exports

### `towerjs`

```tsx
import { defineTower, createTower, createTowerApp, initTower, getTowerApp, tower } from 'towerjs'

defineTower({ modules: { vault: {} } })     // type-safe config (from blueprint)
createTower()                                // auto-resolves tower.config.ts
createTowerApp({ modules: {} })            // explicit config
initTower({ modules: {} })                 // explicit init, returns TowerApp
getTowerApp()                                // get cached TowerApp singleton
tower                                        // TowerApp proxy (throws if uninitialized)
```

`createTower` and `createTowerApp` are re-exports from `@towerjs/foundation` — they do not wire module factories by themselves. Use `initTower()` or `getTowerApp()` (which resolve the config, wire `getModuleFactory`, and lazy-init on first access), or pass `getModuleFactory` from `@towerjs/blueprint` explicitly.

### `towerjs/blueprint`

```tsx
import { defineTower } from 'towerjs/blueprint'
// Type-safe config helper (runtime no-op)
```

For programmatic module access (`registerModule`, `getModuleFactory`, `getModuleDependencies`, `getRegisteredModules`, `getModuleDeclarations`), import from `@towerjs/blueprint` directly.

### `towerjs/foundation`

```tsx
import { createTowerApp, createTower, initTower, getTowerApp } from 'towerjs/foundation'
```

`detectRuntime` and `resolveConfig` live on `@towerjs/foundation` — they are not re-exported from this subpath.

### `towerjs/gatehouse`

```tsx
import { gatehouse } from 'towerjs/gatehouse'
// Fully lazy proxy — awaits tower init, then delegates to @towerjs/gatehouse

const session = await gatehouse.getSession()
const user = await gatehouse.requireUser()
const orgs = await gatehouse.getOrganizations()
```

### `towerjs/gatehouse/next`

```tsx
import { action, withGatehouse, GET, POST } from 'towerjs/gatehouse/next'

// action — wraps a server action in gatehouse request context
export const myAction = action(async (formData: FormData) => {
  const session = await gatehouse.getSession()
})

// GET, POST — auth API route handlers (for api/auth/[...all])
export { GET, POST } // in route.ts
```

### `towerjs/gatehouse/client`

```tsx
import { gatehouseClient } from 'towerjs/gatehouse/client'

await gatehouseClient.signIn.email({ email, password })
await gatehouseClient.signUp.email({ name, email, password })
```

### `towerjs/vault`

```tsx
import { vault } from 'towerjs/vault'
// Lazy proxy — initializes on first access

await vault.selectFrom('users').selectAll().execute()
await vault.migrate()
```

### `towerjs/courier`

```tsx
import { courier } from 'towerjs/courier'

await courier.email.send({ to: 'user@example.com', subject: 'Hi', html: '<p>Hi</p>' })
```

### `towerjs/next`

```tsx
import { action } from 'towerjs/next'
// Next.js server action wrapper (no .form variant)
```

### `towerjs/edge`

```tsx
import { withTowerEdge } from '@towerjs/edge'
// Edge is not re-exported from towerjs — install and import @towerjs/edge directly
```

## Lazy Initialization

The `gatehouse` and `vault` proxies delegate to `getTowerApp()` before every method call, triggering config resolution and module init on first access. The `courier` proxy does not lazy-init — it throws if Tower hasn't been initialized (e.g. via `initTower()` or another module's first use). This means:

```tsx
import { gatehouse } from 'towerjs/gatehouse'

// No init yet — safe to import at module level
export async function handler() {
  // First access triggers config resolution and module init
  const session = await gatehouse.getSession()
}
```

## CLI

The `tower` binary ships with `@towerjs/scribe`, not `towerjs`. Installing `towerjs` alone does not expose it — add `@towerjs/scribe` (or scaffold with `tower create`) to get:

```bash
npx tower migrate          # Run database migrations
npx tower migrate --seed   # Migrate then seed
npx tower seed             # Run seeds (migrations first by default)
npx tower seed --skip-migrate  # Seeds only
npx tower --version        # Show version
```
