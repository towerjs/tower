---
title: "towerjs"
description: "The meta-package that bundles all Tower modules under a single dependency with lazy initialization."
---

`towerjs` is the user-facing entry point. It re-exports from all `@towerjs/*` packages and adds lazy initialization — the app is initialized on first use, not at import time.

## Installation

```bash
pnpm add towerjs
```

## Subpath Exports

### `towerjs`

```tsx
import { defineTower, createTower, createTowerApp, initTower, getTowerApp, tower } from 'towerjs'

defineTower({ modules: { vault: {} } })     // type-safe config (from blueprint)
createTower()                                // auto-resolves tower.config.ts
createTowerApp({ modules: {...} })           // explicit config
initTower({ modules: {...} })                // explicit init, returns TowerApp
getTowerApp()                                // get cached TowerApp singleton
tower                                        // TowerApp proxy (warns if uninitialized)
```

### `towerjs/blueprint`

### `towerjs/gatehouse`


## Lazy Initialization

The `tower` proxy and all module proxies (`gatehouse`, `vault`, `courier`) delegate to `getTowerApp()` before every method call. This means:

```tsx
import { gatehouse } from 'towerjs/gatehouse'

// No init yet — safe to import at module level
export async function handler() {
  // First access triggers config resolution and module init
  const session = await gatehouse.getSession()
}
```

## CLI

`towerjs` exposes a `tower` binary:

```bash
npx tower migrate          # Run database migrations
npx tower migrate --seed   # Migrate then seed
npx tower seed             # Run seeds (migrations first by default)
npx tower seed --skip-migrate  # Seeds only
npx tower --version        # Show version
```
