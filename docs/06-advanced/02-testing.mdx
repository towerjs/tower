Tower uses [Vitest](https://vitest.dev) for unit tests and [Playwright](https://playwright.dev) for E2E tests.

## Unit Tests

```bash
pnpm add -D vitest
```

```ts filename="vitest.config.ts"
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    globals: true,
    environment: 'node',
  },
})
```

### Testing with createTowerApp

```ts
import { getModuleFactory } from '@towerjs/blueprint'
import { createTowerApp } from '@towerjs/foundation'

it('creates an app with vault', async () => {
  const app = await createTowerApp(
    { modules: { vault: { connectionString: process.env.DATABASE_URL } } },
    getModuleFactory
  )
  expect(app.container.has('vault')).toBe(true)
  await app.shutdown()
})
```

The second argument to `createTowerApp` is the module factory resolver. The `getModuleFactory` from `@towerjs/blueprint` resolves modules registered via `registerModule`.

### Testing Gatehouse

```ts
import { gatehouse } from '@towerjs/gatehouse'

it('gets session', async () => {
  const session = await gatehouse.getSession()
  expect(session).toBeNull() // unauthenticated
})
```

## Integration Tests

Integration tests exercise the live database and live in `tests/integration/`. They provision their required local infrastructure automatically:

```bash
# provisions Postgres, runs the suite, then tears it down
pnpm test:integration
```

A global setup drops and recreates the database schema before each run, so integration tests always start from a clean slate. Database-dependent tests check for `DATABASE_URL` and skip gracefully when it's unset.

## E2E Tests

E2E tests live in `examples/with-nextjs/e2e/` and provision their required infrastructure automatically:

```bash
# provisions Postgres + browser, runs the suite, then tears everything down
pnpm test:e2e
```

### Test Patterns

```ts
import { expect, test } from '@playwright/test'

test('user can sign up', async ({ page }) => {
  const email = `test-${Date.now()}@example.com`

  await page.goto('/sign-up')
  await page.fill('[name="name"]', 'Test User')
  await page.fill('[name="email"]', email)
  await page.fill('[name="password"]', 'password123')
  await page.click('button[type="submit"]')

  await expect(page).toHaveURL('/dashboard')
})
```

### Conventions

- Each test generates a unique email (`test-${Date.now()}@example.com`) for isolation
- No database cleanup needed between tests
- Use `test.skip()` for provider-dependent tests (OAuth, etc.)

## Writing Tests

- Unit tests are colocated with source files: `src/**/*.test.ts`
- Integration tests (live DB) go in `tests/integration/`
- Build tests (Next.js production build) go in `tests/build/`
- E2E tests go in `examples/with-nextjs/e2e/`
- Tests should not require external services unless guarded
- Database-dependent tests check for `DATABASE_URL` and skip gracefully
- `pnpm test` is hermetic — it never starts infrastructure. DB and build tiers run explicitly.
