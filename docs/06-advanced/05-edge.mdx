The Edge package configures Tower modules for edge runtime compatibility.

## Setup

```ts filename="next.config.ts"
import { withTowerEdge } from '@towerjs/edge'

export default withTowerEdge({
  // Standard Next.js config options
})
```

`withTowerEdge` wraps your Next.js config to:

1. Bundle `tower.config.ts` for the Edge Runtime (avoids filesystem access at runtime) — it aliases the Tower config through webpack and Turbopack so the bundled config is available in edge functions.

## What Changes on Edge

### Runtime Detection

On Vercel Edge, runtime detection returns `{ name: 'edge', isServerless: true }`. This affects:

- **Vault**: Uses the Neon HTTP dialect (`kysely-neon`) — no connection pool. No filesystem access — migrations and seeds throw if called in edge context.
- **AsyncLocalStorage**: Replaced with a no-op context provider (Edge doesn't support ALS).
- **Lazy initialization**: Still works the same way — first access triggers init.

### Vault on Edge

```ts verify
import type { VaultModule } from '@towerjs/vault'
import { vault } from '@towerjs/vault'

const db = vault as unknown as VaultModule<{ users: { id: string; email: string } }>

// Querying works
const users = await db.selectFrom('users').selectAll().execute()

// Migrations and seeds throw
await (vault as unknown as any).migrate() // Error: migrations unavailable on Edge
await (vault as unknown as any).seed() // Error: seeds unavailable on Edge
```

### Neon Serverless

When using Neon, Vault uses the HTTP dialect from `kysely-neon` on every runtime — including Node.js serverless. No WebSocket pool is involved, which avoids dangling connection issues. SSL defaults to `true` in production.

## When to Use Edge

- API routes that need fast cold starts
- Read-only database queries with Neon
- Pages that don't need migration/seed operations

## Gatehouse on Edge

Gatehouse is provider-boundary driven. The `better-auth` provider requires Node.js APIs for session/cookie handling; custom `GatehouseProvider` implementations can be Edge-compatible.

```ts
import { gatehouse } from '@towerjs/gatehouse'
import type { GatehouseProvider } from '@towerjs/gatehouse'

const edgeProvider: GatehouseProvider = {
  name: 'edge-auth',
  capabilities: {
    runtime: { node: true, edge: true },
    authentication: { password: true },
    sessions: { database: true },
  },
  init: async () => {},
  getSession: async () => null,
  from: async () => ({ session: async () => null }) as any,
} as any

gatehouse({ provider: edgeProvider })
```

A Node-only provider initialized on Edge throws an actionable error (`does not support Edge runtimes`) during `initialize` — the provider's `init` never runs. Vault (Neon HTTP) and Courier work natively on Edge.
