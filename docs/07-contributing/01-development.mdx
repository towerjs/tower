## Repository Structure

```
tower/
├── packages/
│   ├── foundation/       # Core runtime, DI, config
│   ├── blueprint/        # Module registration, app definition
│   ├── vault/            # Database ORM (Kysely + PostgreSQL)
│   ├── gatehouse/        # Authentication (Better Auth)
│   ├── courier/          # Email, SMS, push
│   ├── towerjs/          # Meta-package (user-facing)
│   ├── scribe/           # CLI for scaffolding
│   ├── create-tower/     # pnpm create tower entry
│   └── edge/             # Edge runtime integration
├── examples/
│   └── with-nextjs/      # Reference Next.js application
├── tests/                # Cross-package acceptance tests
├── docs/                 # Documentation content
└── scripts/              # Development scripts
```

## Setup

```bash
git clone https://github.com/hyphenzero/tower
cd tower
pnpm install
pnpm build
```

## Commands

```bash
pnpm build        # Build all packages via Turborepo
pnpm test         # Run all unit tests (vitest)
pnpm test:watch   # Vitest watch mode
pnpm lint         # Lint with oxlint
pnpm typecheck    # TypeScript type checking (tsc --noEmit)
pnpm format       # Format with Prettier
pnpm clean        # Remove all dist directories
pnpm check:deps   # Validate dependency rules
```

## Testing

### Unit Tests

Tests are colocated with source code in `packages/*/src/**/*.test.ts`:

```bash
pnpm test
```

### E2E Tests

E2E tests use Playwright against the demo Next.js app:

```bash
# Start Postgres
docker compose up postgres

# Run tests (auto-starts Next.js dev server)
pnpm test:e2e
```

Tests are in `examples/with-nextjs/e2e/` and cover auth flows: sign-up, sign-in, email verification, sessions, organizations, two-factor auth, password changes, and more.

### Environment for E2E

- Database resets between runs: `docker compose down -v && docker compose up postgres`
- Email uses `console` provider — logs to stdout
- Each test generates a unique email to avoid state conflicts

## Linting

We use **oxlint** (not ESLint or Biome, which are incompatible with TypeScript 7):

```bash
pnpm lint
```

Config is in `oxlint.json` at the root.

## Commit Style

Use conventional commits with the package name as scope:

```
feat(gatehouse): add passkey update action
fix(vault): handle pool close on shutdown
refactor(towerjs): extract facade builder
chore(deps): upgrade vitest
docs(root): update README
```

Scopes: `foundation`, `blueprint`, `vault`, `gatehouse`, `courier`, `scribe`, `create-tower`, `towerjs`, `edge`, `root`.

## Dependency Rules

| Package | Can depend on | Cannot depend on |
|---|---|---|
| `foundation` | (nothing) | any `@towerjs/*` |
| `blueprint` | `foundation` | vault, gatehouse, courier, edge, scribe |
| `vault` | `blueprint`, `foundation` | gatehouse, courier |
| `courier` | `blueprint`, `foundation` | vault, gatehouse |
| `gatehouse` | `blueprint`, `foundation`, `courier` | vault |
| `towerjs` | anything | — |

No circular dependencies. Enforced by `tests/dependency-rules.test.ts`.

## Releases

1. `pnpm changeset` — select bumped packages and describe changes
2. `pnpm version` — applies changesets
3. `pnpm release` — builds and publishes

Changeset summaries use plain English, not conventional commit format.
