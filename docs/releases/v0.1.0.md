# Tower v0.1.0 release boundary

The active Changesets queue is intentionally empty for the first public release.
All publishable Tower packages already carry the deliberate baseline version
`0.1.0`; `changeset publish` publishes that baseline without requiring a
version bump. Historical development changesets were consolidated here so
they remain release-note context without accidentally calculating a post-0.1.0
version.

Included development work:

- Courier console provider and email verification support.
- Gatehouse client plugins and permission/API-key fixes.
- Vault Kysely/Neon support and local PostgreSQL SSL-mode handling.
- Scribe migration/seed commands and the Next.js scaffold workflow.
- Tower runtime ordering, React Server Components support, and CLI packaging.

After v0.1.0, every publishable Tower package belongs to the Changesets fixed
group in `.changeset/config.json`. A changeset for one package therefore
versions the entire group together.
