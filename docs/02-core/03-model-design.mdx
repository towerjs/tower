This is the **S3 design** for Tower models (closes #75). It layers an application-facing Model API above the existing Vault/Kysely query API without replacing Kysely, without a second schema language, and without committing to Active Record semantics.

> **Vault stays the engine.** Normal code uses `Project.create()` / `Project.find()`; advanced code uses `vault.selectFrom()`; expert code reaches Kysely's `sql` tag directly. See [Infrastructure](/docs/infrastructure).

## Goals

- Typed fields derived from TypeScript row types — no separate schema DSL.
- CRUD, `find`/`findOrFail`, type-safe results.
- Model-scoped transactions.
- Relationship definitions and eager loading (belongs-to / has-many).
- Query API and named scopes.
- Casts, hidden fields, stable serialization.
- Factories usable from tests, seeds, and E2E.
- `vault` (and `vault.db` alias) remains the escape hatch for raw queries.

## Non-goals

- Replace Kysely or `vault.*` query builder.
- Introduce a second schema language (no `field.string().unique()` DSL).
- Commit to Active Record (`instance.save()` vs `Model.update()` is still open; prototype offers both).
- Cover every Laravel/Eloquent feature in v0.2.

## Layering

```plain
Tower Model API  (Model, defineModel, ModelQuery, Factory)
        ↓
Vault  (vault.selectFrom / insertInto / transaction / schema)
        ↓
Kysely (Dialect = pg | neon, sql tag, Migrator)
        ↓
Postgres
```

`vault` is a `Kysely<Schema>` proxy (see `packages/vault/src/index.ts`). Models delegate to `vault` — provider swap (`provider: 'neon' | 'pg'`) remains a config change with zero query changes.

`vault.db` is an alias to `vault` (raw `Kysely`) for the documented escape hatch:

```ts
import { vault } from '@towerjs/tower/vault'

await vault.db.selectFrom('projects').where(...).execute()
await vault.selectFrom('projects').where(...).execute() // same
```

## Model definition — no second schema language

Model rows are TypeScript types. The table name is the only required declaration. Casts and hidden fields are optional static metadata.

```ts
import { Model } from '@towerjs/vault/model'

type ProjectRow = {
  id: string
  name: string
  description: string | null
  owner_id: string
  created_at: string // db timestamptz, cast to Date
  updated_at: string
}

export class Project extends Model<ProjectRow> {
  static table = 'projects'
  static casts = { created_at: 'datetime', updated_at: 'datetime' } as const
  static hidden = ['owner_id'] as const // omitted from toJSON()
}
```

Alternative functional helper exists for those who prefer not to subclass:

```ts
import { defineModel } from '@towerjs/vault/model'

export const Project = defineModel<ProjectRow>('projects', {
  casts: { created_at: 'datetime' },
  hidden: ['owner_id'],
})
```

Both produce the same `Model` subclass. The prototype ships the class form; the helper is a thin wrapper.

Why not a schema DSL? The database schema already lives in migrations (`src/vault/migrations/*.ts` via `Kysely`/`sql`). Duplicating it as `field.string().notNull()` would require keeping two sources in sync. TypeScript row types plus `casts` are sufficient for v0.2; a future `tower make model` can generate the row type from the migration if desired, but we don't block on it.

## Typed fields and instance shape

- `Model<T>` is generic over the row type `T`.
- Instances carry `T` plus an `attributes` bag; `model.get('name')` is typed as `T['name']`, `model.set({ name: '...' })` is `Partial<T>`.
- Getters proxy to attributes so `project.name` also works when the key exists in `T` (via `Proxy` or explicit getters in the prototype).
- `created_at` etc. are cast on read/write (see Casts).

## CRUD and identity

```ts
const project = await Project.create({ name: 'Acme', description: null })
// → Project instance, id generated by db (returningAll)

const found = await Project.find(project.id) // Project | null
const same = await Project.findOrFail(project.id) // throws if not found

project.set({ name: 'Acme 2' })
await project.save() // update changed fields where id = ?

await project.update({ name: 'Acme 3' }) // alias for set + save

await project.delete() // delete where id = ?
await project.refresh() // reload from db

await Project.all() // Project[]
await Project.destroy(id) // static delete
```

Primary key is `id` by convention; override with `static primaryKey = 'uuid'` if needed. Composite keys are out of scope for v0.2.

Transactions are model-scoped via `vault`:

```ts
import { vault } from '@towerjs/vault'

await vault.transaction(async (trx) => {
  await Project.create({ name: 'A' }, { trx })
  await Project.create({ name: 'B' }, { trx })
})

// or Model helper
await Project.transaction(async (trx) => {
  await Project.create({ name: 'A' }, { trx })
})
```

Static methods accept `{ trx?: Vault }`; instance methods also accept it. The prototype's `transaction` builds a `Vault` trx via `vault.transaction`.

## Query API and scopes

Models expose a Kysely-backed query builder that returns model instances:

```ts
const projects = await Project.query().where('name', '=', 'Acme').orderBy('created_at', 'desc').limit(10).get()
const first = await Project.query().where('owner_id', '=', userId).first()
const count = await Project.query().where('name', 'like', '%acme%').count()

// sugar
await Project.where('name', '=', 'Acme').first()
await Project.where('owner_id', '=', userId).get()
```

Named scopes are static query fragments:

```ts
class Project extends Model<ProjectRow> {
  static table = 'projects'
  static scopes = {
    recent: (q) => q.orderBy('created_at', 'desc').limit(20),
    ownedBy: (ownerId: string) => (q) => q.where('owner_id', '=', ownerId),
  } as const
}

await Project.scope('recent').get()
await Project.scope('ownedBy', userId).get()
```

Scopes compose: `Project.query().scope('recent').where(...)`. The prototype implements `scope` on the builder; full named-scope registration lands in S4 (#77).

Type-safe results: `Project.query().select(['id', 'name']).get()` narrows to `Pick<ProjectRow, 'id' | 'name'>` instances; `count()` returns `number`. The prototype preserves Kysely's `SelectQueryBuilder` typing via `ModelQueryBuilder<T, Selected>`.

## Relationships and eager loading (S4 — design preview)

```ts
class Project extends Model<ProjectRow> {
  static table = 'projects'
  static relations = {
    owner: () => belongsTo(User, { foreignKey: 'owner_id' }),
    tasks: () => hasMany(Task, { foreignKey: 'project_id' }),
  } as const
}

class Task extends Model<TaskRow> {
  static table = 'tasks'
  static relations = {
    project: () => belongsTo(Project, { foreignKey: 'project_id' }),
  } as const
}

// eager load
const project = await Project.query().with('tasks').findOrFail(id)
project.tasks // Task[]
const tasks = await Task.query().with('project').where(...).get()

// lazy
const owner = await project.related('owner') // User | null
const tasks2 = await project.related('tasks') // Task[]
```

Design choices:

- `belongsTo` / `hasMany` helpers return a relation descriptor (foreignKey, references, related model).
- Eager loading via `with('relation')` does a single additional query per relation (N+1 avoided in S4 via batched loads).
- Prototype stubs `with`/`related`; full eager-loading strategy and typings land in #76.

## Casts and serialization (S5 — design preview)

```ts
class Project extends Model<ProjectRow> {
  static table = 'projects'
  static casts = {
    created_at: 'datetime', // string <-> Date
    metadata: 'json', // jsonb <-> object
    budget: 'number',
  } as const
  static hidden = ['secret_token', 'owner_id'] as const
}

project.created_at // Date (cast from db string)
project.metadata // object (parsed)

project.toJSON() // hidden fields omitted, casts applied
project.toArray() // alias
project.toJSON({ hidden: [] }) // override
```

Cast types in v0.2: `string` | `number` | `boolean` | `datetime` | `json`. Custom casts are a function `(value, direction: 'get'|'set') => any`. Hidden fields are omitted from `toJSON()`/`toArray()` but remain on the instance.

## Factories (S5 — design preview)

Factories build valid rows for tests/seeds/E2E via the model API:

```ts
import { defineFactory } from '@towerjs/vault/factory'

export const ProjectFactory = defineFactory(Project, ({ faker }) => ({
  name: faker.company.name(),
  description: faker.lorem.sentence(),
}))

await ProjectFactory.create() // insert and return Project
await ProjectFactory.create({ name: 'Override' })
await ProjectFactory.createMany(5)
ProjectFactory.make({ name: 'Not persisted' }) // instance without insert
ProjectFactory.states({ archived: { name: '[archived] Acme' } })
```

Factories use `Model.create` internally, so they honor casts and go through the same provider boundary. Seeds can call `await ProjectFactory.createMany(10)`.

## Open questions (not blocking S3)

- Active Record `save()` vs Data Mapper `Repo.update()`: prototype supports `instance.save()`/`update()`/`delete()` plus static `Model.create`/`destroy`; we haven't committed to requiring `save()` everywhere.
- Dirty tracking: prototype tracks `original` vs `attributes` for partial updates; full dirty APIs later if needed.
- Timestamps: `created_at`/`updated_at` handling — auto-set on create/update if columns exist, or leave to db defaults? Prototype leaves to db/migration.
- Pagination: `paginate(page, perPage)` on query builder — deferred to S4.
