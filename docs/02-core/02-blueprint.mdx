Blueprint is the app-definition layer inside `@towerjs/tower`. It is not a publishable package.

## defineTower

Type-safe config helper. A runtime no-op that provides types. Pass an explicit `modules` array of callable module definitions:

```ts
import { courier } from '@towerjs/courier'
import { gatehouse } from '@towerjs/gatehouse'
import { defineTower } from '@towerjs/tower/blueprint'
import { vault } from '@towerjs/vault'

export default defineTower({
  modules: [
    vault({ connectionString: process.env.DATABASE_URL }),
    gatehouse({ provider: 'better-auth', credentials: { enabled: true } }),
    courier({ email: { provider: 'console' } }),
  ],
})
```

Each `vault()` / `gatehouse()` call is both the config factory and the runtime handle (`vault.selectFrom`, `gatehouse.getSession`). See [Vault](/docs/vault) and [Gatehouse](/docs/gatehouse).

## Module Definitions

`defineTower` takes `TowerConfig { modules: TowerModule[] }` where each `TowerModule` carries its own identity and lifecycle:

```ts signature
interface TowerModule {
  name: string
  dependsOn?: string[]
  register?(ctx: TowerContext): void | Promise<void>
  initialize?(ctx: TowerContext): Promise<void>
  shutdown?(ctx: TowerContext): Promise<void>
}
```

Example (from `@towerjs/vault`):

```ts signature
export const vault = new Proxy(createVaultModuleDefinition, {
  get(_target, prop) {
    /* lazy runtime */
  },
  apply(_target, _thisArg, args) {
    return createVaultModuleDefinition(...args)
  },
}) as ((config?: VaultConfig) => TowerModule) & VaultModule
```

`createTowerApp` validates `dependsOn`, topologically sorts, then calls `register` (sync) and `initialize` (async) in order. Missing dependency → actionable error (`Gatehouse requires the Vault module. Add vault()`).

## Dependency Validation

Before initialization, Blueprint validates the module graph:

- All `dependsOn` entries are present in `modules`
- No circular dependencies exist
- Order is resolved via `resolveDependencyOrder` (topological sort)

If validation fails, an error is thrown with details about the conflict.

## Config Helpers

```ts
import { defineTower, env } from '@towerjs/tower/blueprint'
import { vault } from '@towerjs/vault'

export default defineTower({
  modules: [vault({ connectionString: env.string('DATABASE_URL') })],
})
```

`env.string`, `env.optional`, `env.url`, `env.boolean`, `env.number` read lazily for Edge/SSR safety.

## Module Lifecycle

Each module follows a two-phase lifecycle:

1. **`register(ctx)`** — synchronous setup. Register services in the container.
2. **`initialize(ctx)`** — async setup. Start connections, run migrations, etc.

Shutdown is the reverse of initialization: modules are shut down in reverse dependency order.
