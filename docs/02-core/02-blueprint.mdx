Blueprint provides the module system that ties all Tower packages together.

## defineTower

Type-safe config helper. A runtime no-op — it provides TypeScript types. Module configs are `Record<string, unknown>`-shaped (per-module autocomplete lives in each module's own config helper):

```ts
import { defineTower } from '@towerjs/tower/blueprint'

export default defineTower({
  modules: {
    vault: {},
    gatehouse: {
      provider: 'better-auth',
      credentials: { enabled: true },
    },
  },
})
```

## Module Registration

Modules self-register at import time:

```ts
// registers 'courier' module
import '@towerjs/courier'
// registers 'gatehouse' module
import '@towerjs/gatehouse'
// registers 'vault' module
import '@towerjs/vault'
```

Each registration includes a name, dependency list, and factory function:

```ts
registerModule({
  name: 'gatehouse',
  dependsOn: ['vault'],
  factory: (config) => defineGatehouse(config as GatehouseConfig),
})
```

The `@towerjs/tower` meta-package handles all imports automatically.

## Module Declaration

```ts
interface ModuleDeclaration {
  name: string
  dependsOn: string[]
  factory: (config: unknown) => TowerModule
}
```

## Module Factory

```ts
import { getModuleFactory } from '@towerjs/blueprint'

const factory = getModuleFactory('vault')
// → ModuleFactory | undefined
```

## Dependency Validation

Before initialization, Blueprint validates the module graph:

- All dependencies are registered
- No circular dependencies exist
- Dependency order is resolved (topological sort)

If validation fails, an error is thrown with details about the conflict.

## Programmatic Access

```ts
import {
  getModuleDeclarations,
  getModuleDependencies,
  getModuleFactory,
  getRegisteredModules,
  registerModule,
} from '@towerjs/blueprint'
```

## Module Lifecycle

Each module follows a two-phase lifecycle:

1. **`register(ctx)`** — synchronous setup. Register services in the container.
2. **`initialize(ctx)`** — async setup. Start connections, run migrations, etc.

Shutdown is the reverse of initialization: modules are shut down in reverse dependency order.
